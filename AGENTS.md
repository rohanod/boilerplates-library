# Repository Instructions

The original repository is:

- https://github.com/ChristianLempa/boilerplates-library

Before creating or implementing a requested tool in this repository:

1. Check the original repository to see whether that tool is already implemented there.
2. If it exists, clone or fetch the original repository and copy the existing implementation, along with any files it requires, into this repository.
3. Only create a new implementation when the original repository does not already contain one.

Clone the original repository into a temporary or cached location when needed. Do not modify the original repository.

## Creating Docker Compose templates

Invoke the repository-local `create-compose-template` skill before creating or adding a Docker Compose template. Follow its upstream lookup, official-version research, implementation, README update, and verification workflow.

## Copier layout

This repository is one Copier template with a root selector. Do not add nested `copier.yml` files.

Each stack uses this layout:

```text
boilerplates/<name>/
├── questions.yml            # required/core questions
├── options.yml              # questions gated by optional_groups
└── files/
    ├── .copier-answers.yml
    ├── compose.yaml
    └── .env                 # only when needed
```

Use the plain template name for the directory and selector value (for example `boilerplates/karakeep` and `karakeep`). Add new selector values and shared questions to the root `copier.yml`. Required fragments are included before `configure_optional`; optional fragments are included after `optional_groups`. Guard every template-specific question with `template == '<name>'` and its group membership where applicable.

Reuse an existing root question instead of redefining a common name in a fragment. Keep the existing Copier delimiters: `<< >>`, `<% %>`, and `<# #>`. Expose documented settings that are routinely useful; omit debug-only, internal, dangerous, and unwieldy repeatable configuration.

Nginx Proxy Manager is the generated reverse-proxy integration. Proxied Web services join the configured external network with a stable alias and suppress only their direct Web host port. Nginx Proxy Manager itself keeps ports 80, 443, and 81.

Autogenerated credentials use explicit sentinel values in `.env` and the idempotent root Copier task. Do not put generated credentials in `.copier-answers.yml`.

## Releases

When the user asks to commit, push, and merge a template behavior change, treat that as a release request unless they explicitly say not to release. After the change is merged into `main`, create and push one PEP 440-compatible Git tag pointing at that merged `main` commit.

Use semantic versioning: patch for backward-compatible fixes, minor for backward-compatible features or options, and major for removed templates or other incompatible changes. Do not tag documentation-only changes unless the user explicitly requests a release. Verify the pushed tag resolves to the merged `main` commit and report its name and commit.

## Git commits

Do not add co-author trailers (for example `Co-Authored-By`) to commits in this repository.

# Repository Instructions

The original repository is:

- https://github.com/ChristianLempa/boilerplates-library

Before creating or implementing a requested tool in this repository:

1. Check the original repository to see whether that tool is already implemented there.
2. If it exists, clone or fetch the original repository and copy the existing implementation, along with any files it requires, into this repository.
3. Only create a new implementation when the original repository does not already contain one.

Clone the original repository into a temporary or cached location when needed. Do not modify the original repository.

## Creating Docker Compose templates

Invoke the repository-local `create-compose-template` skill before creating or adding a Docker Compose template. Follow its upstream lookup, official-version research, implementation, README update, and verification workflow.

## Copier layout

This repository is one Copier template with a root selector. Do not add nested `copier.yml` files.

Each stack uses this layout:

```text
boilerplates/<name>/
├── questions.yml
└── files/
    ├── .copier-answers.yml
    ├── compose.yaml
    └── .env                 # only when needed
```

Use the plain template name for the directory and selector value (for example `boilerplates/infisical` and `infisical`). Add new selector values and shared questions to the root `copier.yml`. Keep only template-specific questions in `questions.yml`, and guard each with `template == '<name>'`.

Reuse an existing root question instead of redefining a common name in a fragment. Keep the existing Copier delimiters: `<< >>`, `<% %>`, and `<# #>`.

Autogenerated credentials use explicit sentinel values in `.env` and the idempotent root Copier task. Do not put generated credentials in `.copier-answers.yml`.

## Git commits

Do not add co-author trailers (for example `Co-Authored-By`) to commits in this repository.
